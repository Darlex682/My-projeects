# SQL Security Demo

Этот репозиторий демонстрирует полный цикл работы с небольшой SQL-базой данных:
создание схемы, воспроизведение типовых уязвимостей и их исправление.
Используется встроенная база SQLite, чтобы проект можно было запустить без
дополнительных зависимостей.

## Возможности
- Скрипт для инициализации тестовой базы данных с пользователями и счетами.
- Набор намеренно уязвимых функций, подверженных SQL-инъекциям.
- Автоматизированные проверки, подтверждающие эксплуатацию уязвимостей.
- Исправленные, параметризованные запросы, демонстрирующие безопасное поведение.

## Быстрый старт
1. Установите Python 3.11+.
2. Инициализируйте базу данных и сразу увидьте, что уязвимости срабатывают:
   ```bash
   python src/run_security_audit.py --refresh-db
   ```
   Вывод покажет только уязвимые сценарии (как будто система ещё не «починена»).
3. «Нажмите кнопку фикса» — добавьте флаг, чтобы включить исправления и убедиться,
   что инъекции больше не работают:
   ```bash
   python src/run_security_audit.py --apply-patch
   ```
4. Чтобы увидеть уязвимый и исправленный сценарии подряд одним запуском, используйте:
   ```bash
   python src/run_security_audit.py --show-both
   ```

## Структура
- `src/db_setup.py` — создание схемы и начальных данных.
- `src/vulnerable_app.py` — уязвимые SQL-запросы, подверженные инъекциям.
- `src/patched_app.py` — безопасные версии запросов с параметризацией.
- `src/vulnerability_tests.py` — сценарии эксплуатации уязвимостей.
- `src/run_security_audit.py` — точка входа для создания БД, запуска тестов и проверок исправлений.

## Как открыть базу данных вручную
База лежит по пути `data/vulnerable.db`. Её можно исследовать стандартной утилитой
SQLite:

```bash
sqlite3 data/vulnerable.db
sqlite> .tables
sqlite> SELECT * FROM users;
```

Альтернатива без интерактивной сессии:

```bash
python -m sqlite3 data/vulnerable.db "SELECT username, balance FROM users JOIN accounts ON users.id = accounts.user_id;"
```

## Чего ожидать от отчёта
Скрипт выводит две секции:
- "Vulnerable query results" — примеры успешной эксплуатации SQL-инъекций.
- "Patched query results" — тот же набор запросов, но уже в безопасном варианте; инъекции там не срабатывают.

## Почему SQLite
SQLite поставляется вместе с Python, поэтому проект не требует установки
дополнительного сервера БД. Логика уязвимостей и их исправлений легко переносится
на другие СУБД (PostgreSQL, MySQL, MSSQL) за счёт использования параметризации.
